The full product includes administration, data onboarding, inventory and suppliers, forecasting, knowledge management, scenario comparison, agent workspaces, action review, execution history, evaluation, and operational settings.

Create distinctive features with clear business behaviour: a policy-change impact view, a scenario comparison lab, replayable historical decisions, explanations of infeasible plans, evidence-linked recommendations, cost-aware agent routing, and a connected 3D warehouse. ONE COHERENT DEFAULT STACK
Use Next.js with TypeScript for the web interface; an accessible component system with Light/Dark/System themes; an interactive chart library; and React Three Fiber for 3D. Use FastAPI, Pydantic, PostgreSQL with pgvector, SQLAlchemy and migrations for the service and data layer. Use a durable Python worker backed by PostgreSQL job and outbox tables. Use Python, LightGBM, PyTorch, and a deterministic optimisation library for modelling and decisions. Use LangGraph for stateful agent orchestration with a provider-neutral model adapter. Store document bytes and model artifacts behind a storage adapter using local storage in development and the approved object store in a deployed environment.

Verify currently compatible versions from official documentation, pin them in lockfiles, and record choices. Prefer a modular codebase with web, API, and worker processes over speculative microservices. Additional infrastructure needs a concrete requirement and recorded tradeoff. Choose a single chart implementation and a single ingestion job path. Use typed, versioned API contracts; server-side validation is authoritative.

REAL DATA AND TRAINED MODELS
Use the user's datasets first. Keep raw files immutable; record hashes, provenance, rights, units, currency, date semantics, and transformations. Provide a mapping and validation interface before ingestion. Quarantine invalid records, make imports idempotent, and prevent accidental mixing of unrelated datasets or tenants. Surface supported capabilities based on the available fields. Missing stock, cost, supplier, lead-time, or warehouse data may be supplied as clearly identified simulation inputs; never silently invent observed records.

Train and evaluate a seasonal naive baseline, LightGBM, and one compact quantile temporal convolutional network using reproducible chronological splits. Use the specification's rules for horizons, features, leakage prevention, interval calibration, and zero-denominator metrics. Keep the predictive task honest when only sales, rather than unconstrained demand, is observed. Save model weights, preprocessing, configuration, data fingerprint, metrics, seeds, and code version. A tiny smoke training run verifies plumbing; full held-out experiments establish research findings. An API call to a pretrained LLM is not the user's custom model-training result.

Do not force the neural model to win. Select a model using validation results and operational requirements. Freeze the comparison protocol before final test evaluation. Compare standard RAG and time-aware verified RAG with the forecaster, optimiser, source corpus, and task set controlled. Record repeated agent trials, failure cases, inference cost, and simulated business outcomes. Apply one change at a time in ablations.

AGENT AND RETRIEVAL BEHAVIOUR
Use a stateful coordinator with explicit planning, retrieval, prediction, optimisation, validation, review, execution, and reconciliation states. Split into additional agents only when independent roles justify it. Enforce tool schemas, tenant scope, time limits, bounded retries, and per-run budgets. The model proposes; deterministic tools calculate money, quantities, dates, and hard constraints. A workflow may complete only when its final state is checked.

Implement hybrid retrieval with reranking and mandatory access, tenant, version, and effective-date filters in the operational product. The R2 experiment may vary effective-date selection only in an isolated read-only research profile over the same authorized documents known at the decision time; disable external adapters in that profile. Tenant permissions and historical knowledge cutoffs remain mandatory in all experiments. Preserve source coordinates or page locations, document identifiers, ingestion time, and applicable dates. Retrieve amendments and conflicts explicitly. Keep untrusted document instructions isolated from tool permissions. Do not execute arbitrary SQL, shell, or URLs generated from retrieved text. Parameterised read tools and fixed business commands should handle normal access.

Store decision summaries, tool calls, citations, validation outcomes, and state changes. Do not expose private model chain-of-thought. Distinguish model uncertainty, evidence completeness, and operational constraint checks instead of inventing a single universal confidence score.

INTERACTIVE DESIGN
Use the visual system and screen specifications in the supporting document. The application must have a professional light theme and dark theme, a system preference, persistent settings, responsive layouts, keyboard access, clear focus, reduced-motion behaviour, and coherent loading, empty, error, stale, and permission states.

Connect 3D, charts, tables, maps, and evidence panels to the same real application state: tenant, product, location, date range, as-of time, model version, scenario, and run identifier.
